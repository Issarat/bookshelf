# 12. เวลา ภาษา และการเปรียบเทียบข้อความ

[สารบัญ](README.md) · [บทก่อนหน้า](indexes-and-pagination.md) · [บทถัดไป](history-and-hierarchies.md)

## จุดเวลากับวันที่ทางธุรกิจ

ใช้ TIMESTAMPTZ สำหรับจุดเวลา และเก็บชื่อเขตเวลาแยกเมื่อต้องรู้บริบทท้องถิ่น เช่น เวลาเปิดสาขาหรือนัดหมายในอนาคต DATE เหมาะกับวันเกิดหรือวันที่ที่ไม่มีความหมายเป็นจุดเวลา

วันหนึ่งในบางเขตเวลาไม่ได้ยาว 24 ชั่วโมงเสมอเพราะ daylight saving กฎ “วันถัดไปเวลาเดิม” จึงอาจต่างจาก “อีก 24 ชั่วโมง” ระบุความหมายให้ชัด

## ค้นหารายการในวันท้องถิ่น

ตัวอย่างวันที่ 19 ตุลาคม 2026 ตามเวลาประเทศไทย:

```sql
SELECT * FROM orders
WHERE ordered_at >= TIMESTAMPTZ '2026-10-19 00:00:00+07'
  AND ordered_at <  TIMESTAMPTZ '2026-10-20 00:00:00+07';
```

ใช้ขอบเขตรวมเริ่มไม่รวมจบ ไม่ใช้ 23:59:59 ซึ่งอาจตกหล่นเศษวินาที ถ้าเขตเวลามี DST ต้องคำนวณแต่ละขอบจากวันที่และเขตเวลานั้น ห้ามยึด offset เดิมตลอดปี

## Collation กับ Encoding คนละเรื่อง

Encoding กำหนดการแทนตัวอักษร ส่วน Collation กำหนดพฤติกรรมเปรียบเทียบและเรียงข้อความ ซึ่งขึ้นกับผู้ให้บริการ locale และการตั้งค่า อย่าสมมติว่า ORDER BY จะเรียงภาษาไทยหรือตัวพิมพ์ต่างกันได้ตามที่ผู้ใช้คาดเสมอ

`LOWER(email)` เป็นกฎที่ระบบเลือก ไม่ใช่คำตอบสากลสำหรับตัวระบุทุกประเภท ต้องระบุว่าจะตัดช่องว่าง สนใจตัวพิมพ์หรือเครื่องหมายกำกับเสียงหรือไม่ และใช้กฎเดียวกันทั้ง validation, UNIQUE และ Query

## Unicode และการทดสอบ

ข้อความที่ดูเหมือนกันอาจมีลำดับ Unicode ต่างกัน กำหนด normalization เมื่อจำเป็นและทดสอบก่อนรวมข้อมูล อย่าแก้ค่าชื่อที่ผู้ใช้ต้องการแสดงโดยไม่แยกจากค่าที่ใช้ค้นหา

การเปลี่ยนเวอร์ชัน collation provider อาจกระทบลำดับและ Index ต้องวางแผนตรวจและบำรุงรักษาตามเวอร์ชันฐานข้อมูล

## แบบฝึกหัด

สร้างชุดทดสอบชื่อไทย อังกฤษ ตัวพิมพ์ต่างกัน ช่องว่างท้าย และเวลาข้ามเที่ยงคืน ระบุผลลัพธ์ที่ธุรกิจต้องการก่อนเลือกฟังก์ชันหรือ Collation

อ่านต่อ: [Date/Time Types](https://www.postgresql.org/docs/18/datatype-datetime.html) และ [Collation Support](https://www.postgresql.org/docs/18/collation.html)
