# 1. พื้นฐานและความสัมพันธ์

[สารบัญ](README.md) · [บทถัดไป](data-types.md)

## เริ่มจากกฎธุรกิจ

SQL ใช้สร้างตาราง แต่กฎธุรกิจเป็นตัวกำหนดว่าควรมีตารางอะไร ตัวอย่างระบบยืมหนังสือ:

- หนังสือชื่อเดียวกันมีหลายสำเนา
- สมาชิกยืมได้หลายสำเนา
- สำเนาหนึ่งถูกยืมค้างพร้อมกันได้เพียงรายการเดียว
- ต้องเก็บประวัติการยืมและคืน

| ตาราง | หนึ่งแถวแทนอะไร |
|---|---|
| `books` | ข้อมูลหนังสือหนึ่งฉบับพิมพ์ตามขอบเขตที่ระบบกำหนด |
| `book_copies` | สำเนาที่มีอยู่จริงหนึ่งเล่ม |
| `members` | สมาชิกหนึ่งคนหรือหนึ่งบัญชีตามกฎระบบ |
| `loans` | การยืมหนึ่งครั้ง |

แยกหนังสือออกจากสำเนา เพราะหนังสือเดียวกันอาจมีอยู่จริง 5 เล่ม และแต่ละเล่มถูกยืมต่างเวลากัน

## แยกสิ่งของออกจากเหตุการณ์

ถ้าเก็บ `member_id` และวันยืมไว้ใน `book_copies` อย่างเดียว เมื่อคนใหม่ยืมต่อก็ต้องเขียนทับ และประวัติคนก่อนจะหาย จึงใช้ `loans` เก็บแต่ละครั้ง

`due_at` คือกำหนดคืน ส่วน `returned_at` คือเวลาคืนจริง ในตัวอย่างกำหนดให้ `NULL` หมายถึงยังไม่คืน

## รูปแบบความสัมพันธ์

| รูปแบบ | ตัวอย่าง | วิธีแทน |
|---|---|---|
| หนึ่งต่อหลาย | หนังสือกับสำเนา | Foreign Key ใน `book_copies` |
| หนึ่งต่อศูนย์หรือหนึ่ง | สินค้ากับรายละเอียดหนังสือ | Foreign Key ที่เป็น `UNIQUE` หรือ Primary Key |
| หลายต่อหลาย | หนังสือกับผู้เขียน | ตารางเชื่อม `book_authors` |

`UNIQUE(member_id)` ในตารางที่อยู่บังคับว่าสมาชิกมีที่อยู่ได้ไม่เกินหนึ่งรายการ แต่ไม่ได้บังคับว่าสมาชิกทุกคนต้องมีที่อยู่

## Grain: หนึ่งแถวแทนอะไร

กำหนด Grain ก่อนเลือกคีย์ เช่น `order_items` อาจแทน:

- สินค้าหนึ่งชนิดในคำสั่งซื้อ: ใช้คู่ `(order_id, product_id)` ได้
- หนึ่งบรรทัดสินค้า: หากสินค้าเดิมอยู่หลายบรรทัดเพราะโปรโมชั่นต่างกัน ควรมี `order_item_id`

เมื่อความหมายเปลี่ยน คีย์และข้อกำหนดห้ามซ้ำต้องเปลี่ยนตาม

## ข้อมูลบนความสัมพันธ์

ลำดับผู้เขียนอยู่ใน `book_authors.author_order` เพราะคนเดียวกันเป็นลำดับต่างกันในแต่ละเล่มได้ เช่นเดียวกับจำนวนสินค้าที่อยู่ใน `order_items` ไม่ใช่ `products`

## ข้อมูลเฉพาะประเภท

ข้อมูลร่วมอยู่ใน `products` และข้อมูลเฉพาะอยู่ใน `book_details`:

```sql
CREATE TABLE book_details (
    product_id BIGINT PRIMARY KEY REFERENCES products(product_id),
    isbn TEXT UNIQUE,
    page_count INT NOT NULL CHECK (page_count > 0)
);
```

นี่คือ Shared Primary Key: คีย์เดียวเป็นทั้ง Primary Key และ Foreign Key แต่ยังไม่ได้ห้ามสินค้าปรากฏในตารางรายละเอียดประเภทอื่นพร้อมกัน

ใช้ `LEFT JOIN` เมื่อต้องการสินค้าทั้งหมดรวมที่ไม่มีรายละเอียดหนังสือ ใช้ `INNER JOIN` เมื่อต้องการเฉพาะที่มีแถวสัมพันธ์
