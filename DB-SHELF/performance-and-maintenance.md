# 19. ติดตามประสิทธิภาพและบำรุงรักษา

[สารบัญ](README.md) · [บทก่อนหน้า](backup-and-restore.md) · [บทถัดไป](partitioning.md)

## เริ่มจากอาการและหลักฐาน

เก็บค่าตั้งต้นก่อนแก้: เวลาตอบสนองที่ผู้ใช้พบ ปริมาณคำขอ จำนวนแถว ขนาดข้อมูล และทรัพยากร การเพิ่ม Index ไม่แก้เวลาที่เสียไปกับเครือข่าย Connection Pool หรือการรอ Lock ทุกกรณี

| สิ่งที่ดู | ช่วยแยกปัญหา |
|---|---|
| Query ช้าและจำนวนครั้ง | คำสั่งช้ารายครั้ง หรือคำสั่งเล็กที่ถูกเรียกจำนวนมาก |
| Active sessions และ wait events | กำลังคำนวณ รอ I/O หรือรอ Lock |
| อายุ Transaction | มีงานหรือ Connection ค้างหรือไม่ |
| แถวที่คาดกับแถวจริง | Planner ประเมินผิดมากหรือไม่ |
| ดิสก์และการเติบโต | ข้อมูล Index, WAL หรือไฟล์ชั่วคราวโตจากอะไร |

## แผน Query

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT loan_id FROM loans
WHERE member_id = 10 AND returned_at IS NULL;
```

ANALYZE รันจริง ใช้ Query และสภาพแวดล้อมที่เหมาะสม ดู estimated/actual rows, loops, การเรียง และ buffer activity ร่วมกัน ไม่ใช้เวลาเพียงครั้งเดียวตัดสิน

ทดสอบข้อมูลที่มีการกระจายใกล้จริง เช่น สมาชิกส่วนใหญ่มีรายการน้อย แต่บางคนมีประวัติจำนวนมาก Index ที่ช่วยกรณีหนึ่งอาจไม่เหมาะอีกกรณี

## Statistics และเครื่องมือ

`pg_stat_activity` ช่วยดูงานปัจจุบัน ส่วน `pg_stat_statements` ช่วยสรุป Query หากติดตั้งและตั้งค่าไว้ ต้องตรวจสิทธิ์และต้นทุนการเก็บข้อมูล อย่าสมมติว่ามี extension พร้อมทุกระบบ

Planner ใช้สถิติข้อมูล หากความสัมพันธ์ระหว่างคอลัมน์ทำให้ประเมินผิด อาจพิจารณาสถิติเพิ่มเติมหลังวิเคราะห์สาเหตุ ไม่ควรฝืนปิดแผนบางแบบเป็นคำตอบแรก

## VACUUM และ ANALYZE

UPDATE/DELETE สร้างเวอร์ชันแถวที่ต้องเก็บกวาด VACUUM ช่วยนำพื้นที่ภายในกลับมาใช้และงานป้องกัน transaction ID wraparound ส่วน ANALYZE ปรับสถิติสำหรับ Planner

ตรวจ autovacuum และ Transaction ค้าง VACUUM ปกติไม่ใช่คำสั่งย่อไฟล์คืนพื้นที่ให้ระบบปฏิบัติการทุกครั้ง ส่วน VACUUM FULL เขียนตารางใหม่และมีการล็อกหนักกว่า จึงต้องวางแผน ไม่รันเป็นกิจวัตรโดยไม่มีเหตุผล

## ลำดับแก้ปัญหา

ระบุ Query → ตรวจการรอ → อ่านแผน → แก้ Query/Index/สถิติตามหลักฐาน → วัดซ้ำทั้งการอ่านและต้นทุนเขียน → ติดตามหลังใช้งาน

## แบบฝึกหัด

Query ใช้เวลา 5 วินาที แต่ส่วนใหญ่กำลังรอ Transaction อื่น การเพิ่ม Index อย่างเดียวตอบปัญหาหรือไม่ และควรตรวจเจ้าของ Lock อย่างไร?
