# 26. Data Center — โครงสร้างพื้นฐานที่ระบบข้อมูลทำงานอยู่

[สารบัญ](README.md) · [บทก่อนหน้า](big-data.md)

## Data Center คืออะไร

Data Center คือสถานที่และโครงสร้างพื้นฐานที่รองรับอุปกรณ์คอมพิวเตอร์ เช่น Server, Storage และ Network พร้อมระบบไฟฟ้า การระบายความร้อน และการควบคุมการเข้าถึง เป็นพื้นฐานให้บริการและฐานข้อมูลทำงานได้ ([AWS: Data Center](https://aws.amazon.com/what-is/data-center/))

คำว่า Center จึงหมายถึงศูนย์โครงสร้างพื้นฐาน ไม่ใช่ตารางกลางหรือคลังข้อมูลสำหรับวิเคราะห์ Warehouse และ Lake สามารถทำงานบนโครงสร้างพื้นฐานใน Data Center ได้

## แยกสี่คำให้อยู่คนละบทบาท

| คำ | อธิบายอะไร | คำถามตัวอย่าง |
|---|---|---|
| Big Data | ลักษณะความท้าทายของงานข้อมูล | วิธีเดิมรองรับปริมาณและเวลาที่ต้องการไหวไหม? |
| Data Warehouse | ระบบและแบบจำลองข้อมูลเพื่อวิเคราะห์ | จะนิยามและรายงานยอดข้ามระบบอย่างไร? |
| Data Lake | แนวทางจัดเก็บข้อมูลหลายรูปแบบเพื่อประมวลผลต่อ | จะรักษาข้อมูลและที่มาสำหรับหลายการใช้งานอย่างไร? |
| Data Center | สถานที่และโครงสร้างพื้นฐาน | เครื่องและข้อมูลทำงานอยู่ที่ไหน และรับมือความเสียหายอย่างไร? |

ทั้งสี่คำไม่ใช่ตัวเลือกที่ต้องเลือกเพียงหนึ่งอย่าง ระบบเดียวมีบทบาทเหล่านี้ร่วมกันได้

## สิ่งที่เกี่ยวข้องกับคนออกแบบฐานข้อมูล

| ส่วน | ผลที่ต้องพิจารณา |
|---|---|
| Compute และ Memory | Query, Connection และการประมวลผลพร้อมกัน |
| Storage | ความจุ latency, IOPS, throughput และความทนทาน |
| Network | การเชื่อมแอป การรับข้อมูล และ Replication |
| Power และ Cooling | ความต่อเนื่องของอุปกรณ์เมื่อเกิดปัญหากายภาพ |
| Physical/Logical Access | ใครเข้าถึงเครื่อง ระบบ และข้อมูลได้ |
| Monitoring และการปฏิบัติการ | ใครตรวจพบ แก้เหตุ และกู้บริการ |

Data Center ที่มีไฟสำรองไม่ได้แก้ Query ผิด และ Schema ที่ออกแบบดีไม่ได้ป้องกันทุกเหตุด้านไฟฟ้าหรือเครือข่าย ต้องดูแลทั้งชั้นข้อมูลและโครงสร้างพื้นฐาน

## On-premises, Colocation และ Cloud

- **On-premises:** องค์กรดูแลโครงสร้างพื้นฐานของตนเองตามขอบเขตที่จัดไว้
- **Colocation:** ใช้พื้นที่และบริการสถานที่ของผู้ให้บริการ แต่ขอบเขตการดูแลเครื่องและระบบขึ้นกับสัญญา
- **Cloud:** ใช้ทรัพยากรผ่านบริการของผู้ให้บริการ ซึ่งยังมีโครงสร้างพื้นฐานจริงรองรับอยู่

Cloud ไม่ได้แปลว่าไม่มี Data Center หรือไม่มีหน้าที่ดูแลข้อมูล สิทธิ์ กฎเก็บรักษา และการตรวจ Restore ต้องพิจารณาตามชนิดบริการที่เลือก ไม่เหมารวมว่า Managed Database จัดการทุกเรื่องให้ครบ

## Failure Domain และการกู้คืน

Failure Domain คือขอบเขตที่อาจเสียหายร่วมกัน เช่น เครื่องเดียว Rack เดียว หรือสถานที่เดียว การมี Replica สองเครื่องที่พึ่งพาจุดล้มเหลวเดียวกันอาจไม่ช่วยเมื่อจุดนั้นเสีย

กำหนด RPO/RTO แล้วออกแบบตำแหน่งสำรอง การเชื่อมต่อ และวิธีกู้จริงตามเป้าหมาย ไม่ถือว่ามีหลายสำเนาแล้วเพียงพอ Backup ต้องมีขอบเขตความเสียหายและสิทธิ์ที่เหมาะสม และต้องซ้อม Restore

การอยู่หลายสถานที่เพิ่มระยะทางเครือข่ายและความซับซ้อน โดยเฉพาะการยืนยันการเขียนข้ามที่ ต้องประเมิน latency และพฤติกรรมเมื่อเครือข่ายขาดร่วมกับ [บท Replication](replication.md)

## ตัวอย่างภาพรวมร้านค้าออนไลน์

แอปเขียนธุรกรรมลงฐานข้อมูล → นำข้อมูลไป Lake หรือ Warehouse ตามโจทย์ → สร้างรายงานและข้อมูล ML ทั้งหมดต้องมี Compute, Storage และ Network รองรับ ส่วน Governance ครอบคลุมสิทธิ์ คุณภาพ และวงจรชีวิตข้ามชั้น

ไม่จำเป็นต้องสร้างทุกส่วนตั้งแต่แรก ร้านเล็กอาจเริ่มจากฐานข้อมูลกับการสำรองที่กู้ได้ แล้วค่อยเพิ่มระบบวิเคราะห์เมื่อมีเหตุผลรองรับ

## แบบฝึกหัด

ออกแบบระบบสมมติที่เครื่องฐานข้อมูลหนึ่งเครื่องเสียได้โดยบริการต้องกลับมาตาม RTO ที่กำหนด ระบุ Replica, Backup, จุดล้มเหลวร่วม วิธีเชื่อมต่อใหม่ และขั้นตอนทดสอบ อย่าสรุปว่าได้ความพร้อมใช้งานตามเป้าหมายจากจำนวนเครื่องเพียงอย่างเดียว
