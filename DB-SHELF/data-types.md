# 2. ชนิดข้อมูล NULL และ DEFAULT

[สารบัญ](README.md) · [บทก่อนหน้า](foundations.md) · [บทถัดไป](keys-and-constraints.md)

## วันและเวลา

| ชนิด | ความหมายและตัวอย่าง |
|---|---|
| `DATE` | วันที่ไม่มีเวลา เช่น วันเกิด หรือกำหนดคืนตลอดวัน |
| `TIMESTAMP` | วันเวลาที่ไม่มีเขตเวลา ใช้เมื่อความหมายเป็นเวลาท้องถิ่นตามกฎที่กำหนด |
| `TIMESTAMPTZ` | จุดเวลา เช่น เวลาสร้างรายการ ยืม คืน หรือจ่ายเงิน |

`TIMESTAMPTZ` ไม่เก็บชื่อเขตเวลาต้นฉบับ แต่แสดงจุดเวลาตามเขตเวลาของ session หากต้องรักษา `Asia/Bangkok` เป็นข้อมูลธุรกิจต้องเก็บเพิ่ม

เลือก `due_date DATE` ถ้าให้คืนได้ตลอดวัน หรือ `due_at TIMESTAMPTZ` ถ้ามีกำหนดเวลาที่แน่นอน

## จำนวนเงิน

ใน PostgreSQL `NUMERIC` กับ `DECIMAL` เป็นชนิดเดียวกัน:

```sql
price NUMERIC(10, 2)
```

10 คือจำนวนหลักทั้งหมด 2 คือหลักหลังจุด เหลือก่อนจุด 8 หลัก ค่า `19.999` ถูกปัดเป็น `20.00` ส่วน `REAL` และ `DOUBLE PRECISION` เป็นค่าประมาณ

เงินต้องมี `currency` กำกับ ห้ามรวมต่างสกุลโดยตรง และจำนวนหลักทศนิยมต้องเหมาะกับสกุลเงินและกฎธุรกิจ ไม่ใช่ทุกสกุลใช้สองหลัก

## NULL

กำหนดความหมายให้ชัด เช่น `returned_at IS NULL` หมายถึงยังไม่คืน ไม่ใช่ไม่ทราบวันคืนหลังคืนไปแล้ว

```sql
SELECT * FROM loans
WHERE due_at < CURRENT_TIMESTAMP
  AND returned_at IS NULL;
```

ใช้ `IS NULL` ไม่ใช้ `= NULL` เพราะการเทียบด้วย `=` จะได้ผลไม่ทราบและไม่ผ่าน WHERE

- `COUNT(*)` นับทุกแถว
- `COUNT(returned_at)` นับเฉพาะค่าที่ไม่เป็น NULL
- `SUM(...)` เมื่อไม่มีแถวได้ NULL ใช้ `COALESCE(SUM(...), 0)` หากต้องการศูนย์

## CHECK ไม่แทน NOT NULL

```sql
quantity INT NOT NULL CHECK (quantity > 0)
```

`CHECK` ปฏิเสธเฉพาะ FALSE จึงไม่ปฏิเสธผลที่เป็น NULL หากมีเพียง `CHECK(quantity > 0)` ก็ยังใส่ NULL ได้

บังคับว่าจ่ายสำเร็จต้องมีเวลา โดย `status` ต้อง NOT NULL:

```sql
CHECK (status <> 'succeeded' OR paid_at IS NOT NULL)
```

กฎนี้ยังไม่ห้ามสถานะอื่นมี `paid_at` ถ้าต้องการความหมายสองทางต้องเพิ่มเงื่อนไขให้ครบ

## DEFAULT

`created_at DEFAULT CURRENT_TIMESTAMP` เหมาะเมื่อเวลาบันทึกเป็นค่าเริ่มต้นที่ถูกต้อง แต่ `unit_price DEFAULT 0` อาจซ่อนการลืมส่งราคา

ราคา 0 และจำนวน 1 เป็นค่าเริ่มต้นได้เมื่อกฎธุรกิจตั้งใจเช่นนั้น หากต้องบังคับให้ส่งค่า ควรใช้ NOT NULL โดยไม่ใส่ DEFAULT

ใน PostgreSQL `CURRENT_TIMESTAMP` อิงเวลาเริ่ม Transaction ไม่ใช่นาฬิกาที่เดินใหม่ทุกคำสั่ง หากต้องการเวลาปัจจุบันจริงระหว่าง Transaction ต้องเลือกฟังก์ชันให้ตรงความหมาย
