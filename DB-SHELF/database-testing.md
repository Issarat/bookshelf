# 17. ทดสอบกฎของฐานข้อมูล

[สารบัญ](README.md) · [บทก่อนหน้า](security-views-and-migrations.md) · [บทถัดไป](backup-and-restore.md)

## ทดสอบความหมาย ไม่ใช่แค่ INSERT ผ่าน

ออกแบบกรณีจากกฎธุรกิจ และระบุทั้งผลสำเร็จ ผลที่ต้องถูกปฏิเสธ และสภาพข้อมูลหลังจบ

| กฎ | กรณีที่ควรทดสอบ |
|---|---|
| ห้ามยืมสำเนาค้างซ้ำ | ยืมครั้งแรกผ่าน ครั้งที่สองไม่ผ่าน คืนแล้วจึงยืมใหม่ได้ |
| กำหนดคืนต้องไม่ก่อนวันยืม | ก่อน เท่ากัน หลัง และค่าที่ห้ามเป็น NULL |
| อีเมลไม่ซ้ำเฉพาะ active | ตัวพิมพ์ต่างกัน Soft Delete และกู้บัญชีแล้วชน |
| ห้ามอ้างข้ามบริษัท | อ้างสินค้าจริงแต่ tenant ผิดต้องไม่ผ่าน |
| รักษาประวัติ | แก้สินค้าปัจจุบันแล้ว Snapshot เก่าไม่เปลี่ยน |

## ตัวอย่างทดสอบ UNIQUE

ในฐานข้อมูลทดสอบและมีข้อมูลอ้างอิงครบ:

```sql
BEGIN;
-- เพิ่มรายการยืมที่ยังไม่คืนสำหรับสำเนา 1
SAVEPOINT before_duplicate;
-- ลองเพิ่มรายการยืมค้างของสำเนา 1 อีกครั้ง: ต้องถูกปฏิเสธ
-- หลังได้รับ error ให้รันคำสั่งต่อไปแยกจากคำสั่งที่ล้มเหลว
ROLLBACK TO SAVEPOINT before_duplicate;
-- ตรวจว่ายังมีรายการยืมค้างเพียงหนึ่งรายการ
ROLLBACK;
```

นี่เป็นลำดับการทดลอง ไม่ใช่สคริปต์ assertion สำเร็จรูป ตัวทดสอบอัตโนมัติควรตรวจ SQLSTATE หรือชนิดข้อผิดพลาดที่คาด ไม่ยอมรับ error อะไรก็ได้ เช่น Foreign Key error ไม่ได้พิสูจน์ว่า UNIQUE ทำงาน

## Concurrency ต้องใช้หลาย Connection

การรันคำสั่งเรียงใน Connection เดียวไม่พิสูจน์ race condition ทดสอบสอง Session ที่มีลำดับนัดหมายชัด เช่น เหลือที่นั่งหนึ่งที่ ให้ A ถือล็อก offering และ B พยายามล็อกแถวเดียวกัน เมื่อ A บันทึกแล้ว B ต้องตรวจยอดล่าสุดและไม่เพิ่มเกินความจุ

ตรวจทั้งการรอ ผลสำเร็จ จำนวนแถวสุดท้าย timeout และเส้นทาง retry โดยมีเวลาจำกัด ป้องกันชุดทดสอบค้างไม่สิ้นสุด

## สิทธิ์และ Migration

ทดสอบ RLS ด้วยบัญชีแอปจริง ไม่ใช้ Superuser ทดสอบ tenant ผิดและบริบท tenant หาย ทดสอบ Migration กับข้อมูลเก่าที่มี NULL ค่าซ้ำ และขนาดใกล้เคียงจริง

ใช้ข้อมูลจำลองหรือข้อมูลที่ผ่านการจัดการอย่างเหมาะสม ไม่จำเป็นต้องคัดลอกข้อมูลละเอียดอ่อนมาเพื่อให้ทดสอบสมจริง

## แบบฝึกหัด

เขียนกรณีทดสอบ 5 ข้อของการคืนเงิน โดยต้องมีรับ webhook ซ้ำ คืนบางส่วนหลายครั้ง และคำขอคืนพร้อมกัน
